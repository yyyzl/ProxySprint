# Windows 安装器设计

## 目标与架构

用户从单个 EXE 进入安装向导，安装后按正常 Windows 应用方式启动和卸载。
Flutter 与冻结的 Python 引擎继续从已验证目录运行。
构建链为 build_bundle.py → dist 程序目录 → build_installer.py → Inno Setup → Setup.exe。

## 关键决策

- 使用 Inno Setup 提供安装登记、快捷方式和标准卸载，避免只做自解压程序。
- 只安装给当前用户，写入用户 Programs 与 HKCU 卸载项，不请求管理员权限。
- AppId 固定，重复安装进入同一个程序实例；安装目录可选择，版本来自 Flutter。
- 开始菜单必建，桌面入口可选。安装结束可直接启动；静默验证不会自动启动。
- 使用 Restart Manager 检测安装目录中占用的文件，不主动终止用户的 Clash 客户端。
- 数据目录与安装目录分离，不添加删除用户数据的卸载规则。
- 构建工具仅部署于项目 .tools，固定官方下载与摘要；中文翻译随源代码保留。

## 验证与限制

安装器测试仅在没有已安装 ProxySprint 的环境运行，使用唯一的中文及空格目录。
校验全部安装文件、开始菜单、覆盖安装、系统 PATH 下的真实冻结引擎、
卸载登记和用户数据标记保留。测试日志只留在 Git 忽略的 work 目录。
实际 Windows 窗口另行检查。暂未购买 Windows 代码签名证书。
安装器包含固定 Mihomo，支持独立订阅与文件测速；客户端模式也可复用已有内核。
